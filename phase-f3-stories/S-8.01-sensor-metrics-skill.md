# S-8.01: Implement sensor-metrics Skill (BC-8.02.001 v1.4)

## Narrative

- **As a** SecOps operator
- **I want to** run `/sensor-metrics` to retrieve per-org sensor health telemetry
  from `prism_sensor_health`
- **So that** I can monitor sensor connectivity and data freshness across all registered
  customer orgs without manually querying prism

## Behavioral Contracts

| BC | Title | Version |
|----|-------|---------|
| BC-8.02.001 | sensor-metrics Skill — Per-Org Sensor Health Telemetry via prism_sensor_health | v1.4 |

## Acceptance Criteria

### AC-001 (traces to BC-8.02.001 postcondition 2 — per-org × sensor output completeness)
For each org registered in prism.toml, the skill queries `prism_sensor_health` and
presents per-sensor health status. Each row in the output contains the five canonical
BC-8.02.001 postcondition-2 fields: `org_slug`, `sensor_id`, `last_seen_ts`,
`row_count`, and `error_rate`. Using non-canonical names (`last_event_time`,
`event_count`, `connectivity status`) is a defect — the canonical field names from
BC-8.02.001 postcondition 2 are authoritative.

### AC-002 (traces to BC-8.02.001 invariant — D-DEC-005 carve-out for prism_sensor_health)
`prism_sensor_health` queries are exempt from the per-tenant org_slug scoping
requirement (D-DEC-005 explicit carve-out). The skill must NOT add an
`org_slug = '<org_slug>'` WHERE clause to `prism_sensor_health` queries.

### AC-003 (traces to BC-8.02.001 invariant — D-DEC-006 naming)
The skill lives at `skills/sensor-metrics/SKILL.md` (NOT `skills/metrics/`). The
command is registered at `commands/sensor-metrics.md` (NOT `commands/metrics.md`).
Any deviation from the D-DEC-006 naming constraint is a defect.

### AC-004 (traces to BC-8.02.001 postcondition — announce at start)
The skill emits "I am using the sensor-metrics skill to retrieve sensor health
telemetry." as its first output before any prism call.

### AC-005 (traces to BC-8.02.001 EC-002 — prism_sensor_health returns empty result / no orgs onboarded)
If prism.toml contains no `[[orgs]]` entries (or `prism_sensor_health` returns an empty
result set), the skill reports "No sensors found in prism_sensor_health — have you run
/onboard-customer and /onboard-sensor?" and exits without error.
(BC-8.02.001 EC-002 canonical string verbatim — empty result, no orgs onboarded; distinct from EC-001 which is prism MCP unavailable)

### AC-006 (traces to BC-8.02.001 EC-001 — prism MCP connection unavailable / E-SPEC-024 boot abort)
If `prism_sensor_health` returns E-SPEC-024 (prism MCP boot abort) or the prism MCP
connection is unavailable, the skill reports the error verbatim and advises the user
to check the prism binary path, the RUST_LOG=off env var, and to run /activate to
reconfigure. Silent empty output on prism MCP error is a defect (BC-8.02.001 invariant 3).
(BC-8.02.001 EC-001 — prism MCP unavailable / E-SPEC-024; distinct from EC-002 which is empty result)

### AC-007 (traces to BC-8.02.001 EC-004 — last_seen_ts older than 24h; SENSOR SILENCE per-sensor)
When `prism_sensor_health` returns a row where `last_seen_ts` is older than 24 hours
(`last_seen_ts < now() - INTERVAL 24h`), the skill flags that specific sensor row with
the canonical warning: "SENSOR SILENCE: last seen >24h ago — may indicate sensor
connectivity issue". This applies per affected sensor row; other rows are unaffected.
The data is presented (not an error condition), with the warning inline.
(BC-8.02.001 EC-004 — last_seen_ts > 24h ago; SENSOR SILENCE; per-sensor, not global)

### AC-008 (story-local — continue-on-per-org-error behavior; distinct from BC-8.02.001 EC-003)
If `prism_sensor_health` returns an error for one org, the skill reports the error
for that org and continues presenting results for other orgs.
(story-local extension: per-org error resilience; BC-8.02.001 EC-003 covers the distinct
case of one org having sensors while another has none — shown as "no sensors registered" row)

### AC-009 — VP-SKILL-056 (traces to BC-8.02.001 postcondition 2 / VP-SKILL-056 — per-org × sensor output completeness)
For each row returned by `prism_sensor_health`, the skill output MUST contain all five
required fields from BC-8.02.001 postcondition 2: `org_slug`, `sensor_id`,
`last_seen_ts`, `row_count`, and `error_rate`. No field may be silently omitted.
Mutation kill targets: dropping `error_rate` from a row must cause this assertion to
fail; dropping `row_count` from a row must also cause this assertion to fail.
BATS integration test: `@test "sensor-metrics output contains required fields per
org-sensor pair"`. Test fixture: two-org × two-sensor prism-DTU response (4 rows);
assert all five canonical fields are present in every output row.

**Mixed-org coverage (BC-8.02.001 EC-003):** The BATS integration test fixture MUST also
include a scenario where org-A has sensors (returns rows) and org-B has none (returns
empty). Assert that the output contains telemetry for org-A's sensors AND a distinct
"no sensors registered" row (or equivalent message) for org-B — no org is silently
omitted from the output. This exercises BC-8.02.001 EC-003.
(VP-SKILL-056 — per-org × sensor output completeness; BC-8.02.001 postcondition 2 + EC-003;
integration/BATS per-row field assertion per verification-delta)

### AC-010 — VP-SKILL-057 (traces to BC-8.02.001 VP-SKILL-057)
SKILL.md uses the canonical D-DEC-006 skill name `sensor-metrics` in all internal
references. BATS test `sensor-metrics skill name matches D-DEC-006 (not 'metrics')`
must pass.

### AC-011 (traces to BC-8.02.001 EC-005 — error_rate > 0.0 for a sensor)
When `prism_sensor_health` returns a row where `error_rate > 0.0`, the skill
highlights that sensor row and reports: "Elevated error rate (<value>) — investigate
sensor normalization errors". The actual error rate value must be included in the
message. A row with `error_rate == 0.0` must NOT trigger this warning. Example:
`error_rate = 0.15` → "Elevated error rate (0.15) — investigate sensor normalization
errors".
(BC-8.02.001 EC-005 — elevated error rate surfacing; fail-loud per invariant 3)

### AC-012 (traces to BC-8.02.001 EC-006 — E-CRED-008 keyring miss for a sensor)
When `prism_sensor_health` returns `E-CRED-008` for a sensor (keyring miss), the
skill surfaces the credential error with the message: "Credential not found for
<sensor_id>/<org_slug>. Run /onboard-sensor to provision credentials." The
`/onboard-sensor` remediation instruction MUST appear in the output. Returning empty
data as if the sensor is healthy when E-CRED-008 is returned is a defect per
BC-8.02.001 invariant 3 (fail-loud on prism error).
(BC-8.02.001 EC-006 — E-CRED-008 credential miss + /onboard-sensor remediation)
