# S-5.01: Delta — investigate-event Skill D-029 SAVE-ALWAYS-SUCCEEDS (BC-5.01.001 v1.15)

## Narrative

- **As a** monitoring-loop event investigation component
- **I want** the investigate-event skill to implement D-029 SAVE-ALWAYS-SUCCEEDS
  (Invariant 7 — P25-001/P27-001/P27-002), so that non-FP events always route to
  MARKDOWN_REVIEW_PATH with a review marker, MARKER-WRITE-FAILED fails loud, and
  structural ICD-203 completeness gates fire as pre-routing structural DENY signals
  before D-029 disposition routing (P27-001)
- **So that** no non-FP investigation result is silently discarded when the Write
  tool succeeds but marker emission would otherwise be suppressed

## Acceptance Criteria

### AC-001 (traces to BC-5.01.001 invariant 7 — D-029 non-FP route to MARKDOWN_REVIEW_PATH)
For non-FP disposition verdicts, the investigate-event skill routes to
`MARKDOWN_REVIEW_PATH` and issues a review marker (`create-review` or
`comment-review`). This routing is unconditional for non-FP — it does NOT
depend on `autonomy_enabled`. (P25-001 / D-029)

### AC-002 (traces to BC-5.01.001 invariant 7 — structural completeness gates retained)
Pre-routing structural completeness gates are retained: a structurally incomplete
investigation result (missing required fields) still fails validation before
routing. D-029 means "non-FP always routes to review" not "skip validation on
non-FP path."

### AC-003 (traces to BC-5.01.001 invariant 7 — MARKER-WRITE-FAILED fails loud)
If the review marker write fails (filesystem error, permission denied) for a
MARKDOWN_REVIEW_PATH save, the skill must emit `MARKER-WRITE-FAILED` to audit.log
and fail with a non-zero exit. Silently ignoring a marker write failure on the
non-FP path is a defect. (P27-002 — path-aware WRITE_MARKER / MARKER-WRITE-FAILED)

### AC-004 (traces to BC-5.01.001 invariant 7 — P27-001 structural pre-routing DENY vs D-029 disposition routing; SM-79 kill: markdown-structural-deny-downgraded-to-review)
Structural ICD-203 completeness gates (all 12 ICD-203 headings present +
Alternatives-Considered present + charset-injection validation passes) are
**pre-routing structural DENY** signals that fire BEFORE the D-029 disposition
routing (EC-004/EC-010). They are NOT D-029 routing cases. A structurally
complete investigation always reaches D-029 disposition routing regardless of
disposition value or hard-floor signals; no disposition-/hard-floor-based deny
is possible on the markdown path for a structurally complete investigation. A
disposition-VALUE PARSE_FAIL (all 12 headings present but value non-canonical,
e.g., "probably TP") routes to MARKDOWN_REVIEW_PATH rather than DENY — that is
a D-029 routing case, not a structural completeness failure. (P27-001 —
structural gates retained as pre-routing DENY under D-029; BC-5.01.001 Inv#7
EC-004/EC-010)
**SM-79 kill (markdown-structural-deny-downgraded-to-review, P27-001/EC-010/VP-HOOK-031,
verification-delta v1.29):** Under SM-79, a structurally incomplete investigation (missing
a required ICD-203 heading) is routed to MARKDOWN_REVIEW_PATH with allow+MARKDOWN_REVIEW_PATH
instead of the pre-routing structural DENY. AC-004's assertion that a structurally incomplete
file is DENIED (not routed) discriminates SM-79: the structural DENY assertion fails → dies.
Paired with S-3.02 EC-014 (same scenario from the disposition-guard emitter side).

### AC-005 (traces to BC-5.01.001 invariant 7 — FP path unaffected)
The known-FP fast-path (disposition = FP/known-benign) is NOT affected by this
delta. FP verdicts continue to NOT issue review markers. Only the non-FP path
changes.

### AC-006 — VP-HOOK-031 (traces to BC-5.01.001 VP-HOOK-031)
End-to-end test: a non-FP investigation result goes through investigate-event,
produces a MARKDOWN_REVIEW_PATH save, disposition-guard (S-3.02) detects the
markdown path, emits a review marker, and require-review (S-3.01) consumes it.
The entire chain must pass. VP-HOOK-031 is the cross-hook integration assertion.
Note: S-3.01 (require-review) is transitively available via the S-3.02→S-3.01
dependency; no direct `depends_on` edge from S-5.01 to S-3.01 is required.

### AC-007 (traces to BC-5.01.001 invariant — regression: existing VP-SKILL-018..020 unaffected)
VP-SKILL-018 (7-stage pipeline present), VP-SKILL-019 (prism evidence collection),
VP-SKILL-020 (ICD-203 verdict construction) must continue to pass after this delta.

### AC-008 — VP-SKILL-069 (traces to BC-5.01.001 invariant 8 — org_slug scoping on all PrismQL paths)
All PrismQL queries issued by investigate-event — at Stage 3 (OCSF event lookup)
and in temporal-adjacency queries — must include an explicit `org_slug` WHERE clause.
A query without `org_slug` scoping is a cross-tenant defect. The clause must be
derived from the active org config, not from user-supplied verdict fields.
Cross-tenant queries are prohibited at both query-construction and MCP call sites.
(VP-SKILL-069 — verification-delta vd:426, BC-5.01.001 Inv#8)
