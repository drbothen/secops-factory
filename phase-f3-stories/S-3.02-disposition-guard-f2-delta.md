### D-029 SAVE-ALWAYS-SUCCEEDS (Markdown Route-to-Review)

### AC-007 (traces to BC-3.03.001 D-029 — markdown path always issues review marker)
When the verdict write is via the MARKDOWN_REVIEW_PATH (non-JSON markdown save),
disposition-guard must issue a review marker (`create-review` or `comment-review`)
regardless of `autonomy_enabled` setting. Markdown-path saves NEVER result in
a no-marker outcome. (D-029, P25-001)

### AC-008 (traces to BC-3.03.001 D-029 — MARKER-WRITE-FAILED fails loud)
If the hook fails to write a marker for a MARKDOWN_REVIEW_PATH save (filesystem
error, permission denied), the hook must emit `MARKER-WRITE-FAILED` to audit.log
and fail loud (non-zero exit). Silent marker loss on the markdown path is a defect.

### AC-009 (traces to BC-3.03.001 D-029 — structural completeness gates retained)
Even on the markdown path, pre-routing structural completeness gates are retained.
A structurally incomplete markdown verdict (missing required fields) must still
fail validation before routing. D-029 means "markdown-path always routes to review"
not "markdown-path bypasses validation."

### AC-010 (traces to BC-3.03.001 PC#2 D-029 — GATE 1/GATE 2 are routing annotations, not denies)
On the markdown path (PC#2), GATE 1 (Indeterminate disposition → `hard_floor_triggered=true`)
and GATE 2 (forbidden technique T1003/T1068/T1021/T1041 → `hard_floor_triggered=true`) write
routing annotations to the audit log but do NOT deny and do NOT short-circuit each other.
Both gates execute; each independently sets `hard_floor_triggered=true` if triggered.
Routing then continues to MARKDOWN_REVIEW_PATH. Pre-D-029: gates fired as denies (P25-001
fix). D-029 eliminates all disposition/hard-floor-based denies on the markdown path — only
structural completeness failures (missing headings — P27-001) and infrastructure failures
(MARKER-WRITE-FAILED — P27-002) may still deny on the markdown path.
