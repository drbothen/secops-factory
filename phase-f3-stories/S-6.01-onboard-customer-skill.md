# S-6.01: Implement onboard-customer Skill (BC-6.01.003 v1.7)

## Narrative

As a SecOps operator, I want a `/onboard-customer` skill that provisions a new
customer org in prism.toml with a UUID-v7 org slug and validated Jira project key,
so that downstream sensor onboarding and the monitoring-loop can operate with a
stable, unique org identity.

## Behavioral Contracts

| BC | Title | Version |
|----|-------|---------|
| BC-6.01.003 | onboard-customer Skill — Org Slug/UUID Provisioning and prism.toml Registration | v1.7 |

## Acceptance Criteria

### AC-001 (traces to BC-6.01.003 postcondition 1)
An `[[orgs]]` entry is appended to `prism.toml` with the customer's `org_slug`
(UUID-v7 format), `org_name`, `jira_project_key`, and `spec_dir` before the skill
reports success.

### AC-002 (traces to BC-6.01.003 invariant — UUID-v7)
The `org_slug` written to `prism.toml` must be a valid UUID-v7 string. The skill
must generate this value; the operator must not supply it manually.

### AC-003 (traces to BC-6.01.003 invariant — org_name duplicate prevention; ADJUDICATION P18-005)
If an `[[orgs]]` entry with the same `org_name` already exists in `prism.toml`,
the skill aborts with "Org '<org_name>' already registered" and does not write a
duplicate entry.

**Adjudication (P18-005):** This AC implements org_NAME dedup — the operative behavior.
`org_slug` is a UUID-v7 generated by the skill (never operator-supplied, AC-002), making
`org_slug` collision structurally impossible in practice. BC-6.01.003 EC-003 words its
message as "Org '<org_slug>' already registered" — this is a frozen-spec wording
imprecision (UUID-v7 orgs cannot semantically collide on slug); the OPERATIVE duplicate
gate is on `org_name` (the human-supplied label). This story keeps org_name dedup as the
enforced check. Do NOT change the frozen BC wording.

### AC-004 (traces to BC-6.01.003 invariant — D-DEC-008 jira_project_key charset)
The `jira_project_key` argument must match `^[A-Z][A-Z0-9]+$` (no hyphens, no
lowercase, no special characters). Any value outside this charset must be rejected
with an error message citing the required format before any file write occurs.

### AC-005 (traces to BC-6.01.003 postcondition — customer directory)
A directory `<spec_dir>/customers/<org_slug>/` is created as part of provisioning.
If it already exists, the skill warns rather than fails silently.

### AC-006 (traces to BC-6.01.003 postcondition — prism_describe verification)
After writing prism.toml, the skill calls `prism_describe` to confirm the org
appears in the prism MCP response. The skill reports success only if this check
passes.

### AC-007 (traces to BC-6.01.003 invariant — AD-017)
The skill must never request credential values in chat. Any interactive credential
prompting must use the AD-017 piped-stdin pattern: `echo "<value>" | prism ...`.
The SKILL.md must not contain patterns that could solicit credential values
directly in chat.

### AC-008 (traces to BC-6.01.003 precondition — announce at start)
The skill emits "I am using the onboard-customer skill to provision a new customer
org." as its first output, before any file operation or prism call.

### AC-009 — EC-010 coverage (traces to BC-6.01.003 EC-010 — per-org jira_project_key hyphen violation)
If `jira_project_key` contains a hyphen (e.g., "SEC-OPS"), the skill rejects it
with the canonical error: "Invalid Jira project key 'SEC-OPS': Jira project keys
must be uppercase alphanumeric with no hyphens or spaces — e.g., PRISMDEMO, SEC,
SECOPS." No `[[orgs]]` entry is written.
(BC-6.01.003 EC-010 — per-org jira_project_key charset DENY; P13-002; SM-54 kill — behavioral onboard-customer leg; NOT BC EC-001 which is UUID auto-generate)

### AC-010 — EC-010 variant coverage (story-local variant of BC-6.01.003 EC-010 — lowercase jira_project_key)
If `jira_project_key` contains lowercase letters (non-conformant to `^[A-Z][A-Z0-9]+$`),
the skill rejects it with the same D-DEC-008 charset format error.
(story-local variant of BC-6.01.003 EC-010 lowercase-non-conformant path; distinct from
BC EC-001 (UUID auto-generate) and BC EC-002 (invalid UUID format))

### AC-011 — EC-004 coverage (traces to BC-6.01.003 EC-004 — prism.toml does not exist at expected path)
If prism.toml does not exist at the expected path, the skill reports the missing file,
asks the user to confirm the `spec_dir` path, and creates prism.toml from scratch with
the new `[[orgs]]` entry.
(BC-6.01.003 EC-004 — prism.toml does not exist; NOT BC EC-003 which is org_slug uniqueness gate)

### AC-012 (story-local — prism_describe verification step after write)
If `prism_describe` does not show the new org after registration, the skill
reports "Org not visible in prism_describe — check prism.toml and prism server"
and does NOT emit a success message.
(story-local verification step; no direct BC-6.01.003 EC; distinct from BC EC-004 (missing prism.toml)
and BC EC-003 (org_slug collision))

### AC-013 (story-local — spec_dir validation; no direct BC EC)
If `spec_dir` is not provided or does not exist, the skill prompts for the value
or reports the missing parameter; it does not default to an arbitrary path.
(story-local parameter gate; no direct BC-6.01.003 EC; distinct from BC EC-005 (TOML parse error)
and BC EC-006 (existing customer directory))

### AC-014 — VP-SKILL-076 (traces to BC-6.01.003 verification property VP-SKILL-076)
The SKILL.md documents D-DEC-008 jira_project_key charset constraint prominently
as a Red Flag or Iron Law. BATS test `onboard-customer has D-DEC-008 project key
charset validation` must pass.

### AC-015 — VP-SKILL-077 (traces to BC-6.01.003 invariant 1 / EC-008 — AD-017 credential-decline; verification-delta vd:444)
The onboard-customer skill MUST never request or accept a credential value in the
conversation. Any credential handling uses the AD-017 piped-stdin pattern only:
`echo "<value>" | prism credential set`. SKILL.md must NOT contain prompts or
patterns that could solicit a secret in chat. BATS test
`onboard-customer never solicits credentials in chat (AD-017)` must pass, verifying
SKILL.md structural absence of in-chat credential collection patterns.
(VP-SKILL-077 — AD-017 credential-decline; MIRRORS VP-SKILL-054 for the
onboard-sensor path; verification-delta vd:444)

### AC-016 — VP-SKILL-052 (traces to BC-6.01.003 invariant — UUID-v7 format validation; verification-delta vd:758)
A malformed org_slug that does not conform to UUID-v7 format must be REJECTED before
being written to prism.toml. If the UUID-v7 generator returns a non-RFC 4122 v7 value
(e.g. a UUIDv4 or a random string), the skill must error loudly with "Generated
org_slug is not a valid UUID-v7" and abort without writing. BATS test
`onboard-customer rejects malformed UUID-v7 org_slug` must pass.
(VP-SKILL-052 — onboard-customer UUID-v7 format validation; verification-delta vd:758)

### AC-017 — VP-SKILL-053 (traces to BC-6.01.003 invariant — idempotent directory creation; verification-delta vd:759, P14-005 repurposed)
Re-running `/onboard-customer` for an already-provisioned org MUST NOT modify or
delete the existing `customers/<org_slug>/` directory or its contents. The skill must
detect the already-existing directory, warn the operator ("customers/<org_slug>/ already
exists — skipping directory creation"), and continue. The org's previously written files
are preserved. BATS test `onboard-customer idempotent directory creation` must pass.
(VP-SKILL-053 — idempotent directory creation, P14-005 repurposed meaning;
verification-delta vd:759)

### AC-018 (traces to BC-6.01.003 EC-005 — prism.toml not valid TOML / parse error → STOP, no write)
If `prism.toml` exists but contains a TOML parse error, the skill MUST STOP without
modifying the file. The skill reports the parse error and instructs the user to fix it
manually before re-running: "prism.toml has a TOML parse error at [location]. Fix
manually before running /onboard-customer." The skill MUST NOT write an `[[orgs]]`
entry into a file whose existing content cannot be parsed — doing so risks destroying
existing org data. No partial write is acceptable.
BATS test: invoke `onboard-customer` with a deliberately malformed `prism.toml`
(e.g., unclosed bracket); assert exit non-zero with parse-error message; assert
`prism.toml` is UNCHANGED after the run.
(BC-6.01.003 EC-005 — data-safety gate: STOP on TOML parse error; P16-004 coverage)

### AC-019 (traces to BC-6.01.003 EC-009 — per-org jira_project_key override capture + confirmation message)
When the user supplies a per-org `jira_project_key` (e.g., `ACME`) during
`/onboard-customer`:
(a) The key is validated against `^[A-Z][A-Z0-9]+$` per AC-004/EC-010 charset gate
    before any write;
(b) The `[[orgs]]` entry is appended to `prism.toml` with `jira_project_key = "ACME"`
    alongside `org_slug` and `uuid`;
(c) The skill prints a confirmation message explicitly stating the override semantics:
    "Per-org Jira project key 'ACME' stored for org '<org_slug>'. This overrides the
    global jira_project_key for all disposition-guard create-review/create operations
    on this org. Global key is still used for orgs without a per-org override."
The confirmation message MUST explicitly state that the per-org key overrides the
global key (Invariant #6 lookup order: per-org key first, global key fallback). Absence
of this override-semantics confirmation is a defect per BC-6.01.003 EC-009.
(BC-6.01.003 EC-009 — per-org jira_project_key override capture + confirmation; P10-009;
Invariant #6 lookup order; P16-006 coverage)

## Architecture Compliance Rules

Extracted from architecture/module-decomposition.md and BC-6.01.003:

1. **D-DEC-008 enforcement:** jira_project_key must be validated at skill entry before
   any write; the regex `^[A-Z][A-Z0-9]+$` is non-negotiable. Build-time note: if
   SKILL.md lacks the D-DEC-008 charset rule, VP-SKILL-076 BATS test will fail.
2. **Lifecycle-management module boundary:** skill logic lives in
   `skills/onboard-customer/`. No logic may leak into the monitoring-loop module
   (C-10 boundary per module-decomposition).
3. **Effectful isolation:** file writes and prism MCP calls are effectful; UUID
   generation is pure. Keep generation logic testable without prism dependency.
4. **AD-017 unconditional:** no code path may introduce in-chat credential collection.
   Any credential handling must use piped-stdin pattern.
5. **No base regression suite — new module:** S-6.01 creates `skills/onboard-customer/SKILL.md` and `tests/skills/onboard-customer.bats` from scratch. The BATS suite created by this story IS the initial baseline; no prior suite exists. Red Gate, then implement until all tests pass.
