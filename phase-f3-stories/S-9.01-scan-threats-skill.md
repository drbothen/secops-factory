# S-9.01: Implement scan-threats Skill (BC-9.01.001 v1.2)

## Narrative

- **As a** SecOps analyst
- **I want to** run `/scan-threats` to execute predefined PrismQL hunting queries
  across all registered orgs with prism_describe-guided table enumeration
- **So that** I can proactively detect lateral movement, credential access,
  and exfiltration patterns without manually constructing queries

## Behavioral Contracts

| BC | Title | Version |
|----|-------|---------|
| BC-9.01.001 | scan-threats Skill — Proactive PrismQL Threat Hunt Across All Orgs | v1.2 |

## Acceptance Criteria

### AC-001 (traces to BC-9.01.001 postcondition 1 — prism_describe before queries)
For each org in prism.toml, the skill calls the `prism_describe` MCP tool to enumerate
available tables before executing any hunting query. `prism_describe` is the canonical
MCP call; if an equivalent is ever used it MUST be documented as such in SKILL.md.
This step must precede any query for every org; it is not skippable.

### AC-002 (traces to BC-9.01.001 postcondition 2/3 + invariant 3 — predefined queries only)
The skill executes only queries from the predefined library in
`${CLAUDE_PLUGIN_ROOT}/data/threat-hunt-queries.md` (or equivalent). Queries
are only issued against tables confirmed to exist by `prism_describe` (canonical
MCP call) output. Tables not in `prism_describe` output are silently skipped (not an error).

### AC-003 (traces to BC-9.01.001 postcondition 4 + invariant 2 — org_slug scoping)
Every PrismQL hunting query issued by this skill includes an explicit
`WHERE org_slug = '<org_slug>'` clause (or equivalent scoping mechanism). The
skill never constructs a cross-tenant query. Queries without org_slug scope must
be rejected before execution. (D-DEC-005)

### AC-004 (traces to BC-9.01.001 postcondition 5 — severity grouping; presentation-only note)
Findings are grouped by severity (CRIT, HIGH, MED, LOW) in the output. Findings
with no severity indicator default to MED. NOTE (P15-004): this bucketing is
display-only; scan-threats does not run Stage-5 assess-priority and does not
produce a `scored_priority` verdict field. This mapping must not be used as
input to disposition-guard hard-floor checks.

### AC-005 (traces to BC-9.01.001 postcondition 6 — no-findings message)
If no findings are returned across all orgs for all queries, the skill emits
"No threat indicators found across all orgs" rather than an empty response.

### AC-006 (traces to BC-9.01.001 invariant 1 — prism_describe unconditional per-org)
The `prism_describe` MCP call for each org is non-negotiable. The SKILL.md must document
this as an Iron Law: "Call `prism_describe` before issuing any hunting query for each
org. Do not skip or cache across orgs. `prism_describe` is the canonical table-enumeration
MCP call; any equivalent must be explicitly documented in SKILL.md."

### AC-007 (traces to BC-9.01.001 invariant 4 — fail-loud on prism error)
Prism error codes E-SPEC-024, E-CRED-008 and others must be surfaced per org per
sensor. A failure for one org must not suppress results for other orgs.

### AC-008 (traces to BC-9.01.001 precondition 4 — announce at start)
The skill emits "I am using the scan-threats skill to execute predefined
threat-hunting queries." before any table enumeration or query execution.

### AC-009 — EC-001 (traces to BC-9.01.001 EC-001)
If `prism_describe` returns empty for an org (no sensor tables), the skill skips
that org and reports "No sensor tables available for org <org_slug>" in the
findings summary.

### AC-010 — EC-002 (traces to BC-9.01.001 EC-002)
If a predefined query targets a table not in `prism_describe` output, the skill
skips that query for that org and notes "Table <name> not available for org
<org_slug>" in the diagnostic log; other queries continue.

### AC-011 — EC-003/EC-004 (traces to BC-9.01.001 EC-003/EC-004)
If one org returns CRIT findings and another returns none, CRIT findings are
presented prominently; the clean org gets "No threat indicators found" separately.
If all orgs return zero rows, the skill emits "No threat indicators found across
all orgs."

### AC-012 — EC-005 (traces to BC-9.01.001 EC-005)
If prism MCP is unavailable (E-SPEC-024), the skill reports E-SPEC-024 and
instructs the user to check prism binary, MCP config, and run /activate.

### AC-013 — EC-006 (traces to BC-9.01.001 EC-006)
If E-CRED-008 occurs for one org's sensor, the skill reports the credential miss
for that org/sensor and continues with other orgs.

### AC-014 — EC-007 (traces to BC-9.01.001 EC-007)
If a hunting query returns more than 1000 rows, the skill truncates to the top 100
findings, reports "Truncated — top 100 findings shown", and instructs using more
targeted queries for full analysis. The retained count is explicitly 100 — the BATS
assertion MUST verify exactly 100 rows are returned, not an unspecified N.

### AC-015 — EC-008 (traces to BC-9.01.001 EC-008)
Findings lacking a severity field default to MED severity with a note in output
that severity was defaulted.

### AC-016 — VP-SKILL-058 (traces to BC-9.01.001 VP-SKILL-058)
SKILL.md workflow documents prism_describe call as the first step before any
hunting query for each org; "enumerate tables before querying" step is present.
BATS test `scan-threats has prism_describe enumeration step before queries` must pass.

### AC-017 — VP-SKILL-059 (traces to BC-9.01.001 VP-SKILL-059 — UPGRADED structural→behavioral, P10-005)
Two-part requirement per VP-SKILL-059 behavioral upgrade:

**(a) Multi-org DTU behavioral fixture (SM-24 kill target):** using a prism-DTU
multi-org fixture with orgs a, b, c (`--config-dir <tmpdir>`), an org-a threat hunt
run MUST return ZERO rows from org-b or org-c tables. This exercises the runtime
org_slug scoping guarantee and kills SM-24 (org_slug-drop: a hunt returns cross-tenant
rows when org_slug scope is dropped from the query).

**(b) Static parse of data/threat-hunt-queries.md:** parse every query entry in
`data/threat-hunt-queries.md` and assert that EVERY library query carries an explicit
`org_slug` scope clause (e.g. `WHERE org_slug='<org_slug>'` or equivalent). The test
MUST fail if any query in the library is unscoped — a SKILL.md prose grep is NOT
sufficient; the library file itself must be statically verified.

(SKILL.md structural Iron Law / Red Flag retained per VP-SKILL-059 structural leg;
verification-delta vd:765, P10-005 upgrade)
